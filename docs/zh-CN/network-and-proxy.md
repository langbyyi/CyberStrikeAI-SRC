# 代理池与项目 OpenVPN

全局代理池位于左侧「代理池」，项目指定代理和 VPN 在「项目设置 → 项目网络」中配置。全局节点供用户和 Agent 共享，项目下发的私有代理及 VPN 仅供对应项目使用。

创建项目时填写测试目标和测试要求，再选择项目网络模式。使用 OpenVPN 时上传厂商提供的 `.ovpn`、外置证书和私钥；内嵌证书无需重复上传。需要 `auth-user-pass` 的配置同时填写 VPN 用户名和密码，支持只有 CA 加账号密码，也支持客户端证书与账号密码并用。自然语言测试范围由 Agent 理解并登记，系统负责连接、重连和断开，无需用户在测试过程中逐个维护代理或发现的资产。

## 三种模式

| 模式 | 行为 |
| --- | --- |
| 默认网络 | Agent 可调用全局池，按目标验证并选定一个节点；未申请时沿用原网络。 |
| 项目指定代理 | 支持带认证的 HTTP、HTTPS、SOCKS5、SOCKS5H 地址，例如 `socks5://127.0.0.1:1080`；固定节点不可被 Agent 用全局池覆盖。 |
| 项目 OpenVPN | 每个项目独立 Linux network namespace、TUN、DNS 和规则；两个项目可同时连接不同 VPN，支持相同目标私网地址。 |

项目固定出口失败时阻止需要该出口的目标连接，不切回直连或全局池。VPN 尚未就绪时仍可启动已隔离的本地命令，网关中的非目标请求保持基线路径。模型 API、搜索、FOFA 以及平台自身的网络请求不进入项目 namespace。验证直接经代理向目标发送 GET；2xx/3xx 表示对目标可用，401/403/429/5xx 标为不可用并保留 HTTP 状态与原因。HTTP 拒绝不等于节点断网，不能仅因此全局删除节点。

## 全局池

管理员可通过「手动添加代理」「导入订阅」「自动采集」三个入口添加节点。支持 URI 列表、Base64、Clash YAML 和 V2Ray JSON；原生接入 HTTP、HTTPS、SOCKS5。VMess、VLESS、SS、Hysteria2 等隧道协议显示未接入数量，可先在运行主机的客户端中加载，再添加该主机可访问的 HTTP / SOCKS 端口，不会将隧道节点误当作普通代理。

自动爬取支持 FOFA、Quake、Hunter、ZoomEye、Shodan 和订阅，单次上限 10000 个节点。凭据一律复用系统配置的对应 API Key（Hunter 亦可用 `HUNTER_API_KEY` 环境变量），采集界面不再单独填写来源密钥。填写查询后点击「爬取」，系统自动保存当前配置并开始爬取，完成后保留查询，重复点击复用当前配置。来源在后台保存，弹窗不展示来源历史或额外的保存、全部来源、选中来源操作。任务最长 20 分钟，可取消并保留已导入结果。不内置来源不明的免费代理爬虫，可填写自己的订阅链接。

订阅内容最多 2 MiB；URL 导入每次最多 20 个，后台保存来源供后续同步。订阅抓取不跟随重定向，订阅服务地址需为公共地址。自有内网节点可直接手动导入。

全局池是共享工具目录：导入的共享节点一经启用即可被所有用户和 Agent 直接调用，无逐节点使用许可或确认门槛。因此请仅导入自有、已获授权或明确允许使用的来源；这里不提供密码猜测或破解。项目下发的私有节点不出现在全局列表中。

「代理验证配置」初始目标默认百度 https://www.baidu.com，可保存其他测试 URL、可选响应字符串和连续失败处理（默认保留、阈值 3）。已有自定义设置保留；显式保存为空会跳过验证，不会伪造可用状态；字符串匹配使用最多 1 MiB 的 GET 响应，其他验证检查连接。全池 / 选中验证单次最多 10000 个节点，最多 8 个并发；「验证候选」仍是 Agent 逐目标少量诊断。两类结果分列展示，不用页面字符串匹配结果覆盖 Agent 连通性缓存。清理仅针对连接或代理认证连续失败；目标拒绝访问、限速、内容不匹配不累计清理，全部无响应时暂停清理。项目私有节点和被项目策略引用的节点受到保护。

选中节点可批量启用、停用或删除；删除需要界面确认。作业失败显示已完成数量，取消后刷新已持久化结果，未提交的当前验证批次不会标记完成。

六个 `network_*` 工具默认勾选「常驻」，由可编辑的工具白名单控制，不属于不可关闭的系统内置常驻。旧配置首次加载会补齐默认勾选；用户取消并保存后，重启不会重新勾选。后台以 `network_tool_defaults_applied` 记录默认值已初始化。预置的 17 个非默认角色已加入这些工具；默认角色本身使用全部工具。自定义角色的工具限制仍然生效。

Agent 使用 `network_status`、`network_diagnose` 查看单个节点对当前目标的结果。`network_status` 默认每页 10 个节点，`limit` 支持 1–20，按返回的 `next_offset` 继续查询。支持 `status=all/enabled/disabled/passed/failed/untested` 和 `protocol` 筛选；`summary` 统计完整候选集合，`total` 为筛选后的分页总数。传 `target` 时依据该目标的历史观察，不传时依据最近全池验证，过期结果归为未验证。`passed` 不包含已停用节点。`execution` 返回当前项目、对话、运行标识及本任务最新 `selected_lease`（无租约时为 null），便于核对实际执行上下文；读取状态不会连接或切换代理。节点分页采用固定 ID 顺序，验证结果变化不会使后续页跳过或重复节点。`execution.target_lease` 为当前目标已有的代理租约，`selected_lease_matches_target` 判断最新命令租约是否匹配目标，`needs_acquire_for_exec_target` 表示执行前是否需要重新申请；`effective_target_mode` 与执行层共用规则，包含固定网络子范围和排除项。`next_action` 给出后续动作；`next_call` 提供符合当前筛选条件的建议工具名和参数，不会自动调用。缺少可信对话上下文或不支持 Linux 隔离执行时会明确提示。切换目标后，即使已有旧租约，也应按提示重新 acquire，再执行本地工具。来源查询和订阅地址不进入工具状态响应。`network_acquire` 接受明确的 `node_id`，不传时最多尝试三个节点。单次探测超时 5 秒，结果有效 5 分钟。连通性按目标、项目策略、节点版本和运行位置分别记录。系统为选中节点创建私有临时网关，不随机轮换整个池。`network_release` 只释放调用任务自己的指定租约；任务结束清理临时出口。

验证不预先请求代理地址，也不先发 HEAD；只进行一次目标 GET，HTTPS CONNECT / SOCKS 握手属于转发所需协议过程。3xx 记录当前目标响应，不自动跟随到其他资产；如需识别返回 200 的拦截页，可配置响应特征。代理 CONNECT 返回 407 与目标 TLS 失败分别报告；CONNECT 成功的 200 不会冒充目标 HTTP 响应。探测期间页面停用节点或修改其配置时，旧结果不能获得新租约，需要重新验证当前版本。

爬取期间删除或修改来源后，旧结果停止入池；已完成的页面诊断始终对应其原目标，打开或保存池验证设置不会改写该目标。项目退出固定代理模式后，旧节点 ID 不再阻止池清理。策略版本变更、租约释放后，旧请求不能重新登记原网络环境；HTTP 客户端发现项目范围发生变化时会拒绝继续请求，需要按新范围重建客户端。

## 任务进度与批量管理

- 爬取、订阅导入、批量验证及目标诊断任务可暂停、继续和取消。暂停会先保存当前页或当前验证批次，再停止发起后续请求；页面显示“正在暂停”直到该步骤结束。
- 爬取按页落库，验证每 8 个节点提交一批，已完成节点立即更新到列表。进度显示已读取页数、新增/跳过数量或验证通过/失败数量，爬取不再等全部结束才显示结果。
- 每页引擎请求最多等待 30 秒；失败会显示引擎、页码与凭据/配额检查提示，保留已导入结果。暂停时间不消耗整项任务的执行时间额度。
- 页面刷新后重新关联本人运行或暂停的任务；短暂断网和列表刷新失败不会丢失任务。继续不会重复执行已提交页或批次。
- 暂停任务仅在当前服务进程中保留执行位置。服务重启后已落库结果保留，但需重新发起未完成操作。VPN 连接不使用这套暂停控制。


代理池列表支持每页 20、50、100、200、500 条，分页栏固定在列表底部。操作列保持单行，编辑通过独立弹窗完成。全部删除针对完整全局池，与当前筛选、分页、选中项无关；点击后显示总数确认，项目固定引用的节点会跳过。

## 测试范围与发现资产

项目描述和测试规范可以用自然语言说明授权范围。网络层执行明确的域名/IP 规则，不通过正则推断自然语言含义；由 Agent 根据当前任务、项目描述和规范解释授权，再登记可执行的网络范围。

1. Agent 先调用 `network_status`，读取 `project_context` 中的当前项目说明、测试规范和 `scope_context`。
2. 初始目标以及过程中发现的自有后端，均在测试请求前调用 `network_bind_asset`。未命中已有明确规则时，需要 `scope_basis` 说明授权依据、`evidence` 说明发现及归属证据，并原样回传当前 `scope_context`。
3. 默认 `scope_origin=discovered` 只登记具体域名或 IP。用户明确授权的通配域名或网段使用 `declared`，并引用原始授权；语义登记入口不接受 IPv4/IPv6 默认路由范围。
4. 项目描述、范围、规范或网络策略修改后，旧判断及缓存执行范围不能继续使用。Agent 应重读上下文并重新判断；页面将失效的语义登记显示为“待 Agent 重新判断”。

明确规则支持域名、URL、`*.example.test`、IP 和 CIDR；通配符不包含根域名，URL 端口参与匹配，路由不按 HTTPS 路径区分。用户可以在项目网络高级设置调整走 VPN 的范围，排除、恢复或添加已有授权内的具体资产。页面保存区分明确范围 `declared_scope` 和 Agent 动态登记，避免把旧判断固化为永久规则。明确排除始终优先，修改会关闭旧环境，后续执行按新规则重新准备。

同一页面引用、CNAME、共用 IP 或相同厂商本身不构成测试授权。发现独立 API 域名或 IP 时，Agent 仍需根据当前授权和证据确认归属；第三方登录、支付和统计服务不会因页面引用自动进入范围。配置路由不授予超出用户要求的测试权限。

目标域名通过项目 DNS 解析，A/AAAA、CNAME 最终地址按原主机归类。共享 CDN/IP 无法仅凭 IP 区分目标和非目标：HTTP/HTTPS 网关按域名分流，原始连接发生分类冲突时拒绝。DNS 解析到某个地址也不代表获得该地址所有端口的扫描授权。

## Linux/Kali 部署

当前实现的 namespace 管理在与本地工具相同的 Linux 主机运行。Windows 可以管理配置和验证代理，但固定网络执行会明确返回不支持。远端 MCP/浏览器进程未提供适配时也会阻止调用，不能保证仅凭代理环境变量接管远端浏览器、App 或小程序。

运行主机需要预先提供 `ip`、`nft`、`iptables`、`setpriv`，VPN 模式还需要 OpenVPN 2.6 或以上版本、`/dev/net/tun`。IPv4 forwarding 应由部署管理员预先启用。程序为自己创建的每个 namespace veth 安装两条有归属标记的 IPv4 转发规则，限定接口和项目地址：出站连接及已建立连接的回包；断开或初始化失败时删除对应规则。namespace 内的目标分流和默认拒绝规则继续生效。程序不修改 FORWARD 默认策略、Docker 链、主机默认路由，不安装软件或启用全局 VPN。

namespace 管理需要 root 权限；实际测试命令通过 `setpriv` 降到专用普通用户，移除 capabilities 并设置 no-new-privileges。设置用户 ID 时使用真实运行账号，不要使用 root UID。该用户需要能读写工具工作目录、执行工具。示例启动方式（先完成原项目部署配置，并将示例账号 `cyberstrike` 替换为实际运行账号）：

```sh
export CYBERSTRIKE_NETWORK_UID="$(id -u cyberstrike)"
export CYBERSTRIKE_NETWORK_GID="$(id -g cyberstrike)"
export CYBERSTRIKE_NETWORK_STATE_DIR=/var/lib/cyberstrike-network
sudo --preserve-env=CYBERSTRIKE_NETWORK_UID,CYBERSTRIKE_NETWORK_GID,CYBERSTRIKE_NETWORK_STATE_DIR ./cyberstrike-ai
```

root 服务为会话创建项目工作目录时，会把最终目录交给配置的网络执行 UID/GID，保证降权命令能写入下载及测试产物；不递归修改已有文件，不开放全局写权限。目录路径逐层以不跟随符号链接的描述符打开后变更属主。上级目录仍需允许该用户遍历，已有产物的权限由部署管理员按实际情况处理。

运行副本使用 `disable-dco` 用户态数据通道。程序创建独立 namespace、局部 NAT 表及 namespace 内默认拒绝的出口规则；断线后目标地址不允许落回宿主默认出口。OpenVPN 的原始配置不会改写，运行副本移除默认路由、脚本/插件/management 等行为，连接失败最多进行五轮进程重试。项目 VPN 在任务间保留连接，点击断开或应用正常退出时清理；非正常掉电后遗留的 `csn-*` 资源需要由管理员核查清理。

目标 DNS 自动读取 `.ovpn` 中的 `dhcp-option DNS` / `DNS6`，也接收 VPN 推送的 DNS；高级设置中的 DNS 可以覆盖配置文件的默认值。首个服务器不可用时尝试其他项目 DNS，UDP 响应截断时改用同一服务器的 TCP；单次交换最多 8 秒。若配置和服务器都没有提供 DNS，在项目高级设置填入厂商 DNS IP。无法取得项目 DNS 时目标域名解析失败，不使用公网 DNS 兜底。外部证书文件名须与配置一致，仅支持无路径的文件名。当前不支持 TAP、动态验证码等交互式认证、加密私钥、PKCS#12、脚本和插件配置。

VPN 账号密码为只写输入，保存后清空输入框，仅显示是否已配置；都留空保留同一项目现有凭据，同时填写两项可更新。已有配置可单独更新凭据，无须重新上传文件；上传新的无密码认证配置会移除原凭据。运行时将裸 `auth-user-pass` 替换为受限目录中的两行认证文件，文件权限 0600，断开时清理，不接受配置引用外部认证文件。旧配置的 `ns-cert-type server` 只在运行副本中替换为现代服务端证书验证。认证拒绝立即停止自动重试，更新凭据或明确点击连接后才能重试，避免错误密码循环提交。

取消连接会取消作业并断开项目环境，界面等待清理完成后刷新断开状态；后续新任务仍可按项目策略自动连接。仅申请网络、没有启动命令的任务也纳入租约清理。高级设置的显式 DNS 覆盖服务端推送；自动 DNS 同时支持 `DNS` 和 `DNS6`，去重后最多 8 个。

部署排障时应区分宿主机本地连接与 namespace 转发：即使未启用 UFW，内核仍可能存在 Docker 等组件维护的 `FORWARD DROP` 策略。项目接口的两条规则插入宿主 FORWARD 链首部，兼容该默认策略；只操作带 `cyberstrike:csn-*` 标记且接口及地址匹配的规则，不清空现有链。规则安装失败会中止创建并回滚已安装部分，初始化回滚或显式断开时的清理错误会返回给调用方。若管理员另有原生 nftables 拒绝链或运行时重载规则，仍需针对该环境排障。Windows 上游 Clash TUN 可能参与虚拟机出站，但应先确认报文已从 Kali 网卡发出，不能仅凭超时归因于 Clash。

原始 TCP/UDP 需要 DNS 分类或已声明 IP/CIDR；未知目标默认拒绝。HTTP/SOCKS 代理模式支持通过临时 HTTP 网关的工具，原始目标连接被拒绝，不会自动 SOCKS 化所有协议。隔离环境的原始非目标 IPv6 不提供基线路由，HTTP 网关仍可通过宿主网络访问非目标。原始 ICMP、SYN/原始套接字扫描等依赖特权的工具不能在降权环境工作；使用支持普通 TCP 连接的模式。

原始网络连接按 IP/CIDR 分流，IP 排除规则优先于包含它的目标网段。带端口的 IP 排除在原始连接层保守地排除整个地址；需要按端口区分时使用 HTTP/HTTPS 网关。IPv6 排除地址的原始连接被阻止，不回落到 VPN。

DNS 新地址会继续加入项目规则；旧地址在本次网络环境存续期间保守保留，断开或修改配置时清空。当前没有按 DNS TTL 删除旧地址的机制，长期任务建议重新连接以刷新。进程间不共享状态写锁，同一状态目录只应有一个服务实例。

## 凭据、备份与事件

代理凭据、证书、配置和策略保存在 AES-GCM 加密的 `state.enc`，密钥为同目录 `state.key`；部署可用 `CYBERSTRIKE_NETWORK_STATE_KEY`（64 位十六进制）注入主密钥，设置后不生成 `state.key`，数据目录泄露不再等于凭据泄露。运行副本仅写入该目录的受限子目录。默认目录为数据库文件旁的 `network`；可用 `CYBERSTRIKE_NETWORK_STATE_DIR` 指定。Linux 创建目录权限 0700、文件 0600；备份和恢复时需要同时保存密钥和密文。节点查询、Agent 工具和项目接口不返回代理密码或 VPN 私钥。「导出代理」由全局配置管理员操作，导出全部共享节点（包括停用节点）的完整 URI，包含已配置账号密码，文件名为 proxies.txt；项目私有代理不混入，响应禁止缓存。

环境重建、租约获取/释放/过期、节点退役与策略版本变更记录在最多 200 条的网络事件日志（`GET /api/network/events`，全局管理员），仅含资源 ID 与原因；用于区分"换了节点"与"换了出口 IP"，并追溯事件发生时的策略版本。代理故障探测按阶段分类记录（DNS、代理认证、TCP、TLS、HTTP 状态、限流），观测有效期默认 5 分钟，可用 `CYBERSTRIKE_NETWORK_OBSERVATION_TTL` 调整（30 秒–1 小时）。

相关接口见[API 参考](api-reference.md#代理池与项目网络)。
