# 项目与任务测试规范

在“新建项目”弹窗或“项目 → 项目设置”中填写 **测试规范**。支持直接粘贴、导入 UTF-8 的 `.md`、`.markdown`、`.txt` 文件，最大 64 KiB；不解析 PDF、Word。正文以纯文本预览，清空正文并保存可移除项目默认规范。

规范可包含允许测试的目标、排除项、禁止操作、请求频率、验证证据和报告格式。项目描述仍仅供团队查阅；测试规范会完整加入 Agent 上下文。

新任务默认保存项目规范快照。对话输入框旁的“测试规范”可预览并选择“使用本任务规范”单独替换。已有消息的任务只能查看，删除消息不会解锁快照。需要改变规范请新建任务。项目后续修改不会改变已创建任务；切换未开始任务的项目时会更新继承规范，保留明确设置的任务覆盖。

任务覆盖正文留空表示本任务不使用规范，不会因切换项目而重新继承。漏洞复测复制源任务的规范快照；旧版本任务没有快照时，复测创建时从项目补充，原任务保持不变。

批量队列在创建时冻结默认规范，新建队列中可设置队列覆盖，或点击“设置单条任务规范”选择条目后应用。任务列表发生变化时会清除单条设置，避免绑定错任务；之后加入队列的条目继承队列快照。未显式指定项目时使用配置的默认项目。运行前再次检查队列所有者的项目访问权限。

Eino 单代理、Deep、Plan-Execute、Supervisor、子代理委派和角色工作流均使用同一快照；工作流审批恢复也会重新读取快照。旧对话和旧队列在下一次执行时补充快照。

规范是 Agent 的执行要求，不能替代平台权限、工具限制、审批或项目授权范围。自然语言频率限制由 Agent 遵守，本功能不新增网络限速器。

## API

- 项目 `POST /api/projects`、`PUT /api/projects/:id`：`testing_specification: {"name":"rules.md","content":"..."}`；更新省略字段时保留，传空正文时清除。
- 对话 `POST /api/eino-agent[/stream]`、`POST /api/multi-agent[/stream]`：`testingSpecification` 为任务覆盖；首次执行后不要重复提交该字段。
- 批量 `POST /api/batch-tasks`：`testingSpecification` 为队列覆盖，`taskTestingSpecifications` 为零起始索引映射，如 `{"1":{"name":"task.txt","content":"..."}}`。
- `GET /api/conversations/:id` 返回 `testingSpecification` 快照，包括 `source`、内容 `hash` 与 `frozen`。项目列表不返回完整规范正文，请通过项目详情读取。

## 验证

```bash
go test ./...
node --test web/tests/*.test.cjs
go build -o cyberstrike-ai ./cmd/server
```

新增测试只使用临时数据库、虚构规则和本地模拟模型，检查继承、覆盖、快照持久化、删除消息后仍锁定、配置默认项目、权限范围、续聊、子代理上下文及实际模型请求。运行数据库、配置、上传规范和浏览器截图均不应提交到 Git。

部署前备份 SQLite。启动时增量添加项目规范字段、会话与队列规范表，以及会话快照冻结标记，不清空原有项目或消息。回退二进制不会删除这些新增数据。
