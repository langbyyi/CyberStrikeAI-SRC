# 会话意图识别优化设计

## 目标

会话意图模块用于决定本轮是否进入主动安全测试流程：

- `chat`：普通对话，不启动扫描或漏洞验证。
- `recon`：信息收集，可以使用收集工具，但不启用漏洞验证闭环。
- `pentest`：用户明确要求对目标进行渗透或漏洞验证，才启用主动测试和记录义务。

模型分类失败不得阻断对话，也不得把已成功完成的规则兜底展示为错误。

## 状态切换

意图标签与会话状态切换分开处理：

- 明确停止测试或明确切换到无关新任务时，进入 `chat` 并清空旧目标和待处理义务。
- “继续、查看进度、总结发现、当前结果”等任务内交流保留上一轮意图、目标和义务。
- 明确信息收集请求进入 `recon`，保留或更新目标，但关闭漏洞验证义务。
- 明确渗透或漏洞验证请求进入 `pentest`；记录义务仍要求存在具体目标。

## 分类流程

1. 一套规则实现同时返回意图、置信度和状态切换信号，避免两套关键词逻辑漂移。
2. 明确信号直接采用规则结果，不调用模型。
3. 只有模糊输入调用模型。
4. 模型请求先使用通用的 `max_tokens` 格式。
5. 仅当网关以 400 或 422 拒绝请求字段时，使用 `max_completion_tokens` 再尝试一次。
6. 401、403、404、429、网络错误和超时不立即重试。
7. 分类总预算不超过 8 秒；失败后使用规则结果。

## 可观测性

- 面向进度事件的来源仅表示有效决策路径，如 `rules_confident`、`rules_fallback`、`llm`。
- HTTP 状态、空响应、解析失败等诊断只写结构化日志。
- 日志不记录模型正文片段，避免回显用户敏感内容。

## 验证

回归测试覆盖：

- 渗透过程中询问进度不会清空目标。
- 明确停止或切换无关任务会清空目标。
- 400/422 只降级重试一次。
- 401/403/404/429 和网络错误不重试。
- `reasoning_content` 可作为结构化结果来源。
- Claude 桥接正确映射两种 token 字段。
- 父 context 取消后立即规则兜底。
- 全仓测试和 `go vet` 通过。
