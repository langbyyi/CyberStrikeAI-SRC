# 执行流程稳健性优化设计

## 目标

让同一次代理执行在流式/非流式、单代理/多代理入口下具有可解释的一致生命周期，并优先修复会造成超长等待、错误重试、并发竞态、幽灵会话状态和“响应成功但未落库”的问题。

## 现状与约束

- `eino_single` 流式入口使用 `agent.eino_single_execution.run_timeout_minutes`，非流式入口固定为 600 分钟。
- 多代理入口的创建、恢复和非流式执行均固定为 600 分钟，当前没有独立的多代理超时配置。
- SSE 写入有互斥锁，但 `clientDisconnected` 在多个回调之间无同步读写。
- Eino 瞬时错误判断依赖宽泛字符串包含，`406`、`quota exceeded` 和普通文本中的 `500` 都可能触发重试；默认最多重试 10 次。
- 删除会话只停止任务和删除数据库记录，不清理 `multiagent` 的进程内执行状态。
- 四条聊天成功路径忽略 `UpdateAssistantMessageFinalize` 返回的错误。
- checkpoint 只恢复 ADK 运行上下文，不恢复覆盖率、控制器和证据状态；finalize gate 在 run loop 结束后改写文本，无法真正继续执行。

## 分阶段方案

### 第一期：生命周期硬化

本期直接实施，保持修改面可控：

1. 新增统一的执行超时选择函数。
   - `eino_single` 的流式和非流式统一使用现有配置，默认 120 分钟。
   - 多代理暂时维持现有 600 分钟语义，但所有入口改为调用同一函数，消除散落常量，为后续配置化保留单一修改点。
2. 将 SSE 断连状态改为原子状态，保留现有写锁，消除回调间数据竞争。
3. 收紧瞬时错误分类。
   - 只重试明确的 HTTP 429/5xx、服务过载和网络瞬断。
   - 401/403/404/406、配额耗尽、上下文/令牌限制直接失败。
   - 默认重试次数从 10 降为 3，单次退避上限从 30 秒降为 10 秒；显式配置仍优先。
4. 删除会话成功后清理对应的进程内执行状态。
5. 最终助手消息落库失败时不再静默返回成功。
   - 流式入口发送错误事件后结束。
   - 非流式入口返回 500。
   - 轨迹保存继续作为非关键附属写入，只记录告警。

### 第二期：可恢复执行状态

采用与 ADK checkpoint 同目录、同 checkpoint ID 的版本化 sidecar：

- `runner-<mode>.ckpt` 保存 ADK 原始断点。
- `runner-<mode>.state.json` 保存执行状态 envelope，包含版本、会话 ID、编排模式和保存时间。
- 状态内容覆盖覆盖率、近期证据、技能去重、死亡工具、会话意图、探测/漏洞标志、熔断计数以及完整执行控制器。
- 保存时先写 ADK 临时文件，再写状态临时文件；任一步失败都不保留可恢复的半套断点。
- 恢复时同时校验两个文件、schema 版本、会话归属和编排模式；缺失、损坏或不匹配均删除该断点并回退全新执行。
- 正常结束时同时删除 ADK checkpoint 与状态 sidecar。
- 进程内状态是运行时缓存；启用 `checkpoint_dir` 后，checkpoint sidecar 是跨进程恢复的事实来源。

### 第三期：统一运行循环与终止策略

实施内容：

- finalize gate 前移到 run loop：未满足终止条件时在同一请求内最多自动续跑两段，不再向最终文本追加内部指令。
- 达到续跑上限仍未闭环时返回面向用户的范围限制说明，不泄露框架 marker。
- 单代理/多代理的流式、非流式入口统一使用任务互斥、取消绑定、超时和 completed/failed/cancelled/timeout 终态。
- 公共生命周期组件统一 timeout、SSE 编码/镜像/串行写入/断连状态、任务所有权、最终回复持久化和终态映射。
- run loop panic 恢复为明确错误，避免 `(nil, nil)` 继续触发 handler 空指针。

## 成功标准

- 单代理流式与非流式使用相同的配置化绝对超时。
- 多代理所有入口不再直接出现 `600*time.Minute`。
- SSE 断连标志不存在无同步读写。
- 406、配额耗尽和文本中的孤立数字不触发重试；429/5xx/网络瞬断仍会重试。
- 默认重试总等待显著缩短，显式配置行为不变。
- 会话删除后对应执行状态不可再读取。
- 最终消息落库失败不会向客户端报告成功。
- checkpoint 恢复后覆盖率、控制器、死亡工具和证据状态与中断前一致。
- 损坏、旧版本或跨会话 checkpoint 不会进入 `Runner.Resume`。
- 定向测试、`go test ./... -count=1`、`go vet ./...`、`go build ./cmd/server` 和 `git diff --check` 全部通过。
